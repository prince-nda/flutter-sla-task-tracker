# SLA Task Tracker

A Flutter mobile app that helps a small software team manage its tasks. Users can create and edit tasks, assign them to team members, set priorities and deadlines, and update the status as work progresses. Every task also gets an SLA status, worked out from its deadline and whether it is finished, so the team can see at a glance what needs attention.

This project was built for Formative Assignment 1 by a group of four.

## Features

- Create, edit and view tasks with a title, description, assignee, priority, deadline and status
- Automatic SLA status for every task: On Track, At Risk, Overdue or Completed
- Dashboard with a count of tasks in each SLA status
- Task list with filtering by SLA status
- Task details screen for reviewing and updating a single task
- Team screen for viewing and managing team members
- Profile screen with a summary of a member's tasks
- Statistics screen with a chart of the team's progress
- Sign in and sign up screens, and a settings screen
- Form validation with clear error messages
- Data is saved on the device, so tasks are still there after the app is closed and reopened

## SLA status rules

The status is calculated from the task's deadline and completion, and it is never stored.

| Status    | When it applies                                                                                                   |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| Completed | The task has been marked done                                                                                     |
| Overdue   | The task is not done and its deadline has passed                                                                  |
| At Risk   | The task is not done and the time left before the deadline is inside a window that depends on the task's priority |
| On Track  | in progress but not yet done                                                                                      |

The rules live in `lib/services/sla_service.dart`

## Tech stack

- Flutter and Dart
- State management with `setState()`
- Local storage with `shared_preferences`

SharedPreferences fits this app because the data is small and simple (a list of tasks and team members), so a full database was not needed.

## Project structure

```
lib/
  main.dart            App entry point and MaterialApp
  app_root.dart        Owns the app data, updates it with setState() and saves it
  models/              Task and TeamMember classes, and the status and priority enums
  services/            SLA rules and SharedPreferences saving and loading
  theme/               Colors, SLA colors, spacing and ThemeData
  utils/               Date formatting, validation helpers and task actions
  widgets/             Reusable components (SLA badge, member avatar, task card, chart, member form)
  screens/             The 11 screens listed above
test/
  sla_service_test.dart   Unit tests for the SLA rules
android/, ios/, web/, windows/, linux/, macos/   Platform folders generated by Flutter
```

## Getting started

### Requirements

- Flutter SDK (the project was developed with Flutter 3.47.2 on the stable channel)
- An Android emulator or a physical Android device
- On Windows, Developer Mode turned on, because plugins such as `shared_preferences` need symlink support (run `start ms-settings:developers`)

### Run the app

```bash
git clone https://github.com/prince-nda/flutter-sla-task-tracker.git
cd flutter-sla-task-tracker
flutter pub get
flutter devices
flutter run
```

Run `flutter devices` first to confirm that your emulator or phone is listed. If more than one device is connected, choose one with `flutter run -d <device-id>`.

### Check the code

```bash
flutter analyze
```

### Run the tests

```bash
flutter test
```

The tests in `test/sla_service_test.dart` cover the SLA rules.
